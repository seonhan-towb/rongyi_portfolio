# 문장 배열을 연습하고 싶어서 시작한 앱

## 첫 사용자는 나 자신

중국어를 공부하면서 HSK 쓰기 영역의 문장 배열 문제가 특히 어려웠습니다. 단어의 뜻을 아는 것과, 그 단어를 문장 안에서 어떤 순서로 놓을지 판단하는 것은 다른 일이었습니다.

제가 접한 학습 앱에서는 단어장 외의 콘텐츠가 유료인 경우가 많았습니다. 문장 배열을 무료로 반복해서 연습할 수 있는 앱을 직접 만들어 쓰고 싶었습니다. 그렇게 롱이를 시작했습니다.

처음부터 중요하게 생각한 것은 편리하고 직관적인 학습 경험이었습니다. 패턴과 뜻을 확인하고, 조각을 직접 배열하고, 다시 볼 문제를 골라 복습하는 흐름을 중심으로 만들었습니다.

## 가장 오래 고민한 것은 데이터 구조

문장 배열 학습을 만들려면 예문을 화면에 표시하는 것에 더해, 문장을 문제로 다룰 수 있어야 했습니다. DB에 데이터를 넣고 앱과 연결하는 과정에서 다음 관계를 함께 고민했습니다.

| 데이터 | 학습에서의 역할 |
|---|---|
| 패턴 | 학습할 문법의 형태와 의미 |
| 예문 | 한국어 뜻과 중국어 기준 문장 |
| 문장 조각 | 사용자가 드래그하고 배열하는 단위 |
| 기준 순서 | 조각을 비교,채점하는 기준 |
| 제출 순서 | 사용자가 만든 배열과 복습에서 다시 볼 답안 |

현재는 조각을 식별자로 구분하고, 사용자가 배열한 식별자 순서를 기준 순서와 비교합니다. 이 순서를 기록해 완료 화면에서 내 답과 기준 답을 다시 구성합니다. 채점에서 사용한 정보가 학습 결과와 복습에서도 이어지도록 한 것입니다.

앱과 API, DB를 직접 연결하면서 콘텐츠 구조와 화면의 요구를 함께 맞췄습니다. 데이터 입력과 백엔드 작업에서 시행착오가 있었지만, 이를 거치며 단어와 예문을 보여주는 기능에서 문장을 직접 구성하는 학습 흐름까지 만들었습니다.

## 학습이 끊기는 지점까지 다루기

화면을 만든 뒤에는 콘텐츠 로딩 실패, 네트워크 단절, 진행 상태 복원과 반복 입력도 학습 경험에 영향을 준다는 점을 확인했습니다.

저장된 콘텐츠를 활용하는 Room 캐시, 목록의 추가 로딩과 스크롤 복원, 일일 학습 기록, 중복 채점 방지를 차례로 다뤘습니다. 최근에는 완료 화면으로 이동하는 이벤트를 화면 구성에서 분리하고, 결과를 목적지에서도 보관하도록 바꿨습니다.

이 작업들은 앱이 보여주는 화면과 그 화면을 유지하는 데이터 처리를 함께 개선하는 과정입니다. 구체적인 상태 처리와 확인 범위는 [구현 상세](03-implementation.md)와 [검증 기록](04-verification.md)에 정리했습니다.

## 처음부터 끝까지 연결한 경험

롱이는 기획, 학습 데이터 구성, Android 앱, API와 DB, 배포를 직접 맡아 진행한 프로젝트입니다. 한 기능을 만들 때도 화면에 필요한 정보부터 서버가 전달할 데이터, 기기에 남길 기록과 다음 학습까지 연결해 판단해야 했습니다.

앞으로도 제가 직접 공부하면서 필요한 기능과 콘텐츠를 조금씩 더하려 합니다. 이 기록에는 그 과정에서 선택한 문제와 구현 방법, 확인한 결과를 남기고자 합니다.
